# Разработка

Основной целевой сценарий — Windows 10/11 x64, Python 3.11 и локальный интерфейс
в браузере. Перед изменениями прочитайте [архитектуру](docs/architecture.md).

```powershell
py -3.11 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe main.py --no-browser
```

Откройте http://127.0.0.1:8765. Для разработки используйте отдельные данные:

```powershell
$env:PRAKTIKA_DATA = "$PWD/.test-data"
$env:PRAKTIKA_PORT = "8766"
.venv/Scripts/python.exe main.py --no-browser
```

Значения задаются в окружении; `.env` автоматически не загружается.

## Проверки перед pull request

```powershell
.venv/Scripts/python.exe -m ruff check .
.venv/Scripts/python.exe -m ruff format --check .
.venv/Scripts/python.exe -m unittest discover -s tests -v
node --check praktika/web/app.js
npx --yes prettier@3.6.2 --check praktika/web
```

Тесты не используют платную модель, настоящие ключи и личные документы.
Node/npm нужны только для проверки синтаксиса JS и форматирования Prettier; приложение их не использует.
Для форматирования: `python -m ruff format .` и `npx --yes prettier@3.6.2 --write praktika/web`.
Для ручной проверки UI: загрузите тестовое задание, составьте план, проверьте
редактирование, чат агента, отмену, предпросмотр и экспорт Word.
Полноценная генерация требует ключа совместимого провайдера и может стоить денег.
Скрипты `tests/smoke_*.py` запускайте только против отдельного тестового сервера:
они создают временные подключения и работы; `smoke_agent.py` обращается в интернет.

Сохраняйте совместимость ранее созданных работ. Для изменения поведения добавляйте
проверку результата, а не копию реализации. Не включайте в PR личные документы,
ключи, папку данных и бинарные сборки. В описании указывайте проблему, изменение
поведения и проведённые проверки. Для UI полезен скриншот с синтетическими данными.

## Сборка и выпуск

См. [инструкцию выпуска](docs/releasing.md). Изменения в `praktika/web` при работе
из исходников видны после обновления страницы. EXE использует свою копию ресурсов:
перед выпуском всегда собирайте его заново.
