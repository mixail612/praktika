# Подготовка публикации и Windows-релиза

## Исходники

`python scripts/package_source.py` создаёт `release/Praktika-source.zip` только из
разрешённого набора файлов: код, веб-ресурсы, тесты, документация и конфигурация CI.
Он не обходит рекурсивно всю папку проекта: личные документы, шрифты, `.venv`, `qa`,
ключи, данные и старые сборки в архив не включаются. Скрипт не заменяет проверку
содержимого исходников: не записывайте реальные секреты в код.

Для первой публикации распакуйте этот архив в новую папку и выполните там:

```powershell
git init -b main
git add .
git diff --cached --stat
git commit -m "Initial public release"
git remote add origin https://github.com/OWNER/REPOSITORY.git
git push -u origin main
```

Замените OWNER/REPOSITORY на свой репозиторий. Лицензия исходников — MIT;
она не распространяется на чужие личные материалы или шрифты из рабочей папки.
Ни GitHub-репозиторий, ни релиз скриптом автоматически не создаются.

## Windows-сборка

На Windows x64 с Python 3.11 запустите `build.bat`. Скрипт устанавливает
инструменты, выполняет lint и тесты, затем собирает `Praktika.spec` и создаёт
`release/Praktika-windows-x64.zip`. В архив входят вся папка программы, README
и LICENSE. Для другого компьютера нельзя копировать один EXE без `_internal`.
Не пересобирайте поверх запущенного EXE; перед закрытием дождитесь завершения заданий.

Workflow **Windows build** запускается вручную через Actions или по тегу `v*`.
Он проверяет соответствие тега версии `praktika/__init__.py`, собирает приложение,
проверяет запуск в изолированной временной папке, затем прикладывает ZIP как artifact.
Workflow не публикует GitHub Release автоматически. Скачайте artifact, распакуйте
его и прикрепите полученный ZIP к релизу вручную после проверки.

Перед тегом:

1. Обновите `__version__` в `praktika/__init__.py` и `CHANGELOG.md`.
2. Убедитесь, что CI прошёл. Запустите приложение из итогового ZIP на Windows.
3. Проверьте подключение роутера, загрузку файлов, генерацию, агент, предпросмотр
   и открытие DOCX в Word. Реальный API используйте только со своим тестовым ключом.
4. Создайте тег той же версии, например `v1.0.0`, и отправьте его в GitHub.

Сборка не подписана цифровой подписью; Windows может показать предупреждение
SmartScreen. Не включайте в релиз приватные документы, установленные шрифты,
папку пользовательских данных и ключи. Для доверенного массового распространения
владелец проекта может добавить подпись сертификатом в отдельном процессе выпуска.
