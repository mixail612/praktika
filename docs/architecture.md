# Устройство проекта

Приложение состоит из локального FastAPI API и интерфейса на обычном HTML/CSS/JS.
Отдельного frontend-сервера, npm-зависимостей и базы данных нет.

| Файл | Ответственность |
| --- | --- |
| `main.py` | Локальный сокет, запуск Uvicorn, окно Windows и открытие браузера |
| `praktika/models.py` | Pydantic-модели работ, блоков, оформления и подключений |
| `praktika/storage.py` | Файлы данных, атомарная запись, настройки, системное хранилище ключей |
| `praktika/server.py` | HTTP-маршруты, проверка локального доступа, загрузка и выгрузка |
| `praktika/materials.py` | Извлечение текста PDF/DOCX/TXT/MD без зависимости от HTTP |
| `praktika/migration.py` | Общее чтение актуального и прежнего формата документа |
| `praktika/generation.py` | Выбор настроек модели, API-клиент, фоновые задания и генерация разделов |
| `praktika/agent.py` | Цикл агента, валидация и атомарное применение правок, отмена |
| `praktika/web_tools.py` | Поиск, чтение публичных страниц и ограничения сетевого доступа |
| `praktika/documents.py` | Стили Word, таблицы, поля оглавления и номеров страниц |
| `praktika/web/` | Состояние интерфейса, редактор, чат, настройки и предпросмотр |
| `tests/` | Автоматические проверки и отдельные интеграционные smoke-сценарии |

## Поток данных

Браузер обращается только к локальному API. Сервер извлекает текст вложений,
сохраняет работу и отправляет контекст выбранному роутеру через Chat Completions.
Глобальный роутер и последняя модель находятся в настройках; модель и старательность
могут уточняться для работы. Генератор и агент используют единый механизм разрешения
этих настроек. Модель отвечает структурированными данными, которые проходят
валидацию перед записью. JSON — внутренний формат, а не пользовательский редактор.

Задания выполняются в пуле потоков, статусы находятся в памяти процесса. Для одной
работы одновременно допускается одно задание; отмена запрещает запись результата
текущего запроса. Уже сохранённые разделы остаются. После перезапуска незавершённые
задания автоматически не продолжаются. Одновременное редактирование в нескольких
вкладках и запуск нескольких серверов с общей папкой данных не поддерживаются.

Файлы работ и подключений записываются через временный файл и замену. Блокировка
работает внутри одного процесса. Ключи не сериализуются с профилем: `ProfileInput`
принимает ключ, `Profile` хранит только настройки. Ключ раскрывается локальным API
только по отдельному запросу из интерфейса.

## Совместимость

`generate_docx_file.py` — отдельный конвертер документов в DOCX без запуска интерфейса.
Общий импорт вынесен в `migration.py`; прежние модули генерации и схем удалены,
поскольку приложение использует модули пакета `praktika`. Синтетический пример прежнего документа:
`tests/fixtures/legacy_work.json`. Конвертация без UI:

```powershell
.venv/Scripts/python.exe generate_docx_file.py tests/fixtures/legacy_work.json example.docx
```

## Решение о Docker

Docker не используется: основной продукт — локальное Windows-приложение с
системным хранилищем ключей и окном управления. Контейнер усложнил бы оба механизма,
добавил установку Docker Desktop и не улучшил бы запуск. Для распространения есть
PyInstaller, для разработки — виртуальное окружение. Серверный многопользовательский
режим потребовал бы отдельной модели авторизации, секретов и хранения данных.
